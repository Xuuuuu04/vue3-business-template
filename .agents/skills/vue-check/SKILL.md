# 检查

从本次改动的最小范围开始，公共代码变化再跑完整检查。

| 情况 | 命令 |
| --- | --- |
| 调试一个业务包 | `npm run check -- --quick --module 包名` |
| 单包提交前 | `npm run check -- --module 包名` |
| 改公共代码，或一批改动做完 | `npm run check` |
| 统一格式，或单独核对格式 | `npm run format`、`npm run format:check` |
| 新增包、页面、步骤或函数位置变化 | `npm run docs` |
| 页面、组件或交互变化 | `npm run test:browser` |
| 交付与发布 | 完整检查、浏览器检查和 `VITE_API_MODE=real npm run build` |

check 会自己重写 `src/generated/version.json` 这类派生文件；新建包、页面、步骤，改 module.ts 或步骤函数位置后，图和函数位置要用 docs 重新生成，check 会直接指出。`npm run docs -- --check` 逐个比较全部生成文件，CI 会跑。

快速检查仍执行结构、单包代码规则、格式、单包测试与代码规则自测，只省略全仓类型检查；普通单包检查保留全仓类型检查。`check` 已包含 Prettier 格式核对，格式报错用 `npm run format` 修正，不手工维护第二套写法。

产品里框架文件和 `.template/base.json` 记下的模板原文逐个一致时，完整检查跳过生成器和模板路径两个模板工具自测，并打印“沿用模板验证”；模板仓库自己、改过框架的产品照常运行。

## 四层验证

| 层 | 要确认什么 | 放在哪里 |
| --- | --- | --- |
| 静态检查 | 文件、依赖方向、声明、代码规则、格式与类型一致 | `check`，启动和打包也检查结构 |
| 动作与框架测试 | 已确认样例的结果、权限、并发与失败状态正确 | 包内 `tests/`、`tests/framework`、`tests/architecture` |
| 浏览器检查 | 用户能输入、点击、返回，错误与结果正确显示 | `tests/browser` |
| 真实后台验证 | 真实账号权限、接口、保存结果和数据来源一致 | 业务自己的隔离环境，方法见 `vue-backend` |

测试只放在能发现该问题的最低一层。纯计算不必启动浏览器；组件行为与页面生命周期必须在浏览器检查。模拟响应验证前端处理，真实保存结果由后台验证，不为同一断言堆四层重复测试。

## 代码规则

| 规则 | 要改什么 |
| --- | --- |
| `comment` | 删除普通 TS、Vue 和 CSS 注释，用名字、类型和测试表达用途；保留编译引用与许可声明 |
| `explicit_any` | 换成具体类型；未确认的数据用 `unknown` 并校验 |
| `empty_catch` | 明确处理错误或继续抛出，不用空 `catch` |
| `file_lines`、`function_lines` | 业务与框架 TS/Vue 文件最多 500 行、函数最多 80 行，超出时按职责拆分；测试回调和 CSS 声明不套用这些长度限制 |

这些限制按前端组件和声明代码的写法制定，不照搬后端函数长度。检查指出哪里超出就整理哪里，不用提高阈值或拆成没有明确用途的小文件。

## 框架保护记录

`framework.lock` 记录 `src/shared`、`src/app`、`tools`、框架测试和关键配置的摘要，防止被顺手改掉。启动、打包和 `npm run check` 都会核对它。

做业务时不要改这些文件。确实要改（比如新增界面组件），先看实际差异，写明用途和影响，再：

```bash
npm run framework -- --accept
```

`--accept` 只更新记录，不代表测试通过。改完之后还要跑检查。

## 写测试

- 预期结果来自 `doc/包名/rules.md` 里确认过的样例，不来自代码现在的输出。
- 一个业务功能一个测试文件，名字说明行为。测试名里写规则编号，如 `R-04：…`，规则旁记测试路径。
- 真实 bug、金额、权限、结果未知、并发这几类要留下可重复的测试。
- 时间和请求顺序使用可控时钟、延迟回复验证；不要用不稳定的长等待，也不要放宽业务期限。
- 测试可观察的输入、输出、请求次数和状态，避免只断言实现细节或文件样板。简单文案和可撤回配置修改不专门堆测试。
- 行为测试优先按文字、角色和名称找元素；尺寸与滚动检查可使用公共组件专用的数据标记。

## 记录和汇报

检查结果写入本机 `var/checks`：整仓存 `full.json`，单包存 `module-包名.json`，快速单包存 `quick-module-包名.json`，互不覆盖；记录包含源码指纹与各阶段耗时。代码改动后旧结果自动标为过期，`npm run project` 分开显示各类结果。快速检查不能替代完整单包检查，单包检查不能写成全仓通过；未运行、失败和跳过的部分保持原状态。演示服务与真实后台分别验证。

检查失败时先看文件、行号和失败样例，修问题本身，再跑同一条命令。不能降低阈值、放宽响应类型、改断言或跳过测试让检查通过；本地通过、远程 CI、真实后台和部署结果分别说明。

## 画面检查

UI 改动按 `vue-ui` 的画面比较说明查看实际页面。检查代码声明的尺寸，也检查真实控件是否把行或面板撑高。公共样式变化要看相关组件、业务样板、窄屏和深色模式。

测试通过只说明所测行为和限制满足预期；画面是否清楚、是否达到用户给的参考，须另行比较与说明。不要以测试数量替代视觉验收。
