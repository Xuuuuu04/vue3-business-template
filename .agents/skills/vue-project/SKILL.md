# 查看项目

用标准项目命令先看整体结构与影响范围再读源码，对齐第一眼就懂与状态看得见。

开工前用结构摘要定位相关业务包、动作与函数位置，免去全仓盲读；排查报错先看运行记录与规则样例，确定出错段后再写最小复现。

```bash
npm run project -- --json
npm run project -- --module 包名 --json
npm run impact -- --base main
npm run runs -- --file 导出.json [--run 编号] [--json]
```

## 定位与排查

1. **用摘要掌握全貌**。`npm run project -- --json` 输出全部业务包、计划与各项检查状态，加 `--module` 展开单个包的页面、动作、步骤与源码行号；整仓、单包与快速检查分开展示，源码变动后旧结果自动标记过期。
2. **用影响分析圈定检查**。`npm run impact -- --base main` 依据当前声明推导受影响范围并给出建议命令；涉及已删除依赖或外部系统调用需人工复核，未实跑的建议命令保留未验证状态。
3. **顺着运行记录查错误**。先在开发工具（`/dev`）的操作记录或用 `npm run runs` 查看失败动作的步骤、规则编号、函数位置、HTTP 状态、等待时长与请求/运行编号（未返回保持缺失），再核对 `doc/包名/rules.md` 样例与测试，复现对应输入定位问题。运行记录仅保存在当前页面内存，刷新后会清空，重要结果以后台记录为准。

## 扩展标准工具与实验边界

1. **优先配置与已有命令**。找代码、判影响、查运行、生成文件与验证优先用项目现有命令；产品差异放 `app.config.ts`、`login.config.ts` 与接口声明，只在配置中声明数据。
2. **按规范扩展新工具**。确需新增复用工具时放到 `tools/` 对应目录，在 `package.json` 登记命令并在对应 Skill 补充用法，提前定义参数、读写边界、非零失败码和单元测试，不另起杂项脚本目录。
3. **隔离临时试验**。一次性试验放在系统临时目录，只连隔离测试数据；确认有价值的失败案例转成包测试后及时清理临时文件。

## 验收

能用 `project` 与 `impact` 准确说出本次修改涉及的包和规则范围，排查定位到具体动作步骤或接口请求并留有回归样例。
