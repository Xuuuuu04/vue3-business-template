# 查看项目

```bash
npm run project -- --json                    # 总览：业务线、开发包、计划缺口、检查状态
npm run project -- --module 包名 --json      # 一个包：页面、动作、步骤、依赖、函数位置
npm run impact -- --base main                # 当前改动影响哪些包，并给出建议的检查命令
npm run runs -- --file 导出.json [--run 编号] [--json]   # 看从「结构与运行」页导出的运行记录
```

- `project` 只在源码指纹一致时才把检查结果显示为当前结果；代码改过，旧结果显示为过期。
- `impact` 读取当前代码里的声明。已经删掉的历史依赖和系统之外的调用要人工确认；它建议的命令还没执行，不能据此说"通过了"。
- 开发时的「结构与运行」页（`/system/console`）能看模块图、动作的步骤、字段来源、函数位置，以及页面内最近 100 次动作的实际运行。运行记录只在当前页面内存里，刷新会丢；重要业务结果以后台为准。

## 出错时

先看「结构与运行」里失败的动作与步骤，再按规则编号和函数位置读代码。请求记录里有真实 HTTP 状态、等待时间、请求编号，后台返回运行编号时也会显示；没有的保持缺失，不要补。
