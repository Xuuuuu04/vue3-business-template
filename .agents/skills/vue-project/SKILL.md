# 查看项目

```bash
npm run project -- --json
npm run project -- --module 包名 --json
npm run impact -- --base main
npm run runs -- --file 导出.json [--run 编号] [--json]
```

- `project` 总览业务包、计划和检查状态；`--module` 展开一个包的页面、动作、步骤、依赖和函数位置。整仓、单包、快速单包结果分开显示，只在源码指纹一致时算当前结果；代码改过，旧结果显示为过期。
- `impact` 读取当前代码里的声明。已经删掉的历史依赖和系统之外的调用要人工确认；它建议的命令还没执行，不能据此说"通过了"。
- `runs` 读取从“操作记录”导出的文件。开发时侧栏左下角的“开发者工具”（`/dev`）提供功能地图、操作记录、页面速度和设计预览。运行记录只在当前页面内存里，刷新会丢；重要业务结果以后台为准。

## 出错时

先看“操作记录”里失败的动作、步骤、规则编号和函数位置，再查 `doc/包名/rules.md` 的样例与测试。请求记录包含真实 HTTP 状态、等待时间和请求编号，后台返回运行编号时也会显示；没有的保持缺失。先定位输入、计算、接口或页面哪一段出错，再复现同一个输入，不整仓猜测或整批重跑。

## 工具扩展

- 找代码用 `project`，判断影响用 `impact`，查运行用 `runs`，建文件用生成器，验证用 `check` 和业务测试；已有命令能做的事不另写脚本。
- 产品差异优先放 `app.config.ts`、`login.config.ts`、主题与接口声明；配置只声明数据，不从配置执行任意脚本。
- 确需复用的新工具放已有 `tools/` 的所属功能处，通过 `package.json` 明确登记入口，在对应 Skill 写用法。先定义参数、只读或写入范围、失败退出码和针对性测试，不新建万能脚本目录。
- 一次性试验放系统临时目录，只连接隔离测试数据；有价值的失败样例转成回归测试，结束后清理临时文件，不绕过正式动作修改真实业务。
