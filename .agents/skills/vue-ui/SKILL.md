# 界面系统

**做任何页面前先读 [页面配方](../../../doc/ui-recipes.md)，选一种配方照骨架填写。** 页面结构只写在那一份里；结构检查会拦下多个主区、多个主要按钮、Card 拼页等写法，按报错改结构，不要删检查。

第一次为产品做页面，先读 [产品交付](../../../doc/delivery.md)，沿用任务、状态接入和完成检查。草稿由页面在确认保存成功后清空；列表失败与空结果分开。

完整任务示例可在 `/dev/examples` 操作，分别展示经营总览、客户列表、活动表单、采购详情和客服会话。入口与复用规则见 `doc/ui-examples.md`；示例只修改本页内存，实际业务保存仍通过已声明动作和接口。不要把示例的内存保存复制成生产数据处理。

读 `src/shared/ui/README.md`，查看 `/dev/design` 中相关组件及 `/dev/examples` 的完整页面（源码在 `src/app/dev/examples/`）。目录一次展示一个示例，可用 `section` 与 `example` 地址参数直接打开并刷新，例如 `/dev/design?section=data&example=table`。组件目录用于操作和比较，业务页面仍按真实任务安排。

先明确用户在此页要完成什么、要先看到什么、主要操作是什么。把唯一主要任务写进页面登记的 `task`。已有品牌要求和用户确认的参考优先，不擅自换成新的视觉风格。

## 页面结构

总览、列表、表单、详情、会话、设置的结构见[页面配方](../../../doc/ui-recipes.md)，这里不再重复。另外注意：

- 主区利用可用空间，但不把输入框、说明段落和空占位框无限拉长。表单保留合适行宽；列表、图和文档预览使用其余空间。
- 导航默认一到两层，当前页与祖先清楚区分。目录的链接与展开操作分开；详情不为了进入菜单而增加一层。
- 不在标题下加固定说明小字。状态行表达实际状态，帮助贴近相关操作。

## 视觉与交互

正文和输入值默认 16px；字段名称、导航和时间可以使用对应的辅助层级。用字重、对比和间距区分主次，不把所有内容做成同一字号、同一颜色或同样的框。

间距、字体行高、分隔与动效使用 [组件尺寸与操作规范](references/component-standards.md)。先沿用公共组件和语义变量，不能把成熟设计系统的建议数值写成所有产品都必须遵守的标准。

当前默认是石墨浅色、浅侧栏与点阵背景质感：画布有品牌色微光与质感，工作表面实色浮起，内容用细边框和轻阴影。质感只在画布和登录品牌区，内容区保持实色；不加假表格、漂浮图形、彩虹渐变和从零滚动的数字。换产品先在 `app.config.ts` 选配色、侧栏和质感，不在页面里改颜色。

## 每页的重点

每页先定一个视觉重点（页面配方表里的“重点”一列），用户打开先看到它。重点之外的内容降低层级，不和重点抢位置；大片空白说明结构没选对，换结构而不是加装饰。

表格按真实内容分配列宽。名称保留足够空间，数字便于比较；次要类型和时间保持克制。检查实际行高，行内按钮不能额外撑高单行数据；多行内容按阅读需要增加高度。图标优先用轮廓表达含义，不默认加彩色底块。

读取、无结果、失败、未知结果和保存中的状态都要可用。返回保留筛选、分页和位置；键盘焦点可见、退出后回到合适位置。手机的宽表局部滚动，弹层和日历完整显示。

## 新增公共能力

先确认已有组件是否能完成任务。新增组件放在 base、layout 或 data，语义色与尺寸由主题维护；导出、登记说明、加入设计预览，再按 `vue-check` 更新框架记录。Reka 触发器不能互相嵌套；提示容器不能缩小菜单行宽度。

新增配色运行主题对比度测试。类型、结构和浏览器检查通过后，仍要检查实际页面。

## 交付画面

页面或公共样式改动时，按 [画面比较与完成检查](references/visual-review.md) 比较实际结果。用户要求局部修改时只检查相关页面；公共样式变化时覆盖对应组件、业务样板、窄屏与深色模式。

汇报分开说明实际改动、行为检查和自己的视觉判断。不要把测试通过或换成浅色写成达到参考，更不能没有比较就宣称超越。
