# 画面比较与完成检查

用于用户给出参考图，或页面反复被评价为拥挤、松散、廉价时。先比较具体差异，再修改，避免每一轮只换颜色和圆角。

## 比较条件

参考与实现采用相同的 CSS 视口、浏览器缩放和相近内容长度。浏览器缩放可能让设置的截图尺寸与实际视口不同，要查看 `innerWidth`、`innerHeight` 和输出图像尺寸。等字体、数据、切页进度和有限动效结束后再截图。

先看整页，再看局部。自动测试用于发现行为与尺寸错误，不能给审美打分。

## 看哪里

| 项目 | 要辨别的具体差异 |
| --- | --- |
| 页面组织 | 用户一眼能看到主要对象和入口；有无重复标题、解释段落与互不相关面板 |
| 字体 | 中文、英文、数字是否一致；主要名称与次要字段是否有层级；是否整页过大或过重 |
| 尺寸 | 行高、按钮、图标、表头与输入是否相称；真实按钮会不会撑高数据行 |
| 留白 | 分组间距是否明显大于组内间距；有没有为填屏扩大空框，或标题到工具条之间断开 |
| 表面 | 工作区、数据区域、浮层是否各自清楚；是否每层都加边框、阴影和底色 |
| 色彩 | 文字有足够对比；选中、悬停、错误和禁用有区别；状态色是否染满整页 |
| 内容 | 使用真实长度的中文、文件名、金额、日期；不能只用短占位文案判断 |
| 操作 | 键盘、取消、返回与焦点恢复可用；窄屏、空结果、错误、长内容没有破坏布局 |

## 例子

文件列表由名称、类型、大小和时间组成。名称是主内容，类型与时间是辅助信息；所有字段都同样醒目会失去层级。48px 的数据行里放 38px 按钮再加上下留白，会使实际行高超出设置，紧凑模式也可能没有效果。检查渲染后的高度，不能只读 CSS 数值。

正文较短的上传或详情页仍应有一个清晰主区。占满空间指整体工作区，不要求把字段、提示或占位框都撑满。帮助可以紧邻操作，补充信息可以展开，不需要另造须知卡片。

Markdown、表格和图片按内容形式显示；代码或未经支持的格式明确说明。文件图标、类型标记和预览要帮助识别当前对象，而不是为了多一种颜色。

## 完成判断

修改后回看同一视口和同一内容，指出改善的具体位置。至少走通与改动相关的操作，保留代表画面，让用户能检查。

确认参考未达到时如实说明差异，继续处理已经明确的问题。自己的视觉判断不能替代用户验收。没有用户反馈前，只能说明这一版完成了哪些改善，不能宣布审美要求全部满足。
