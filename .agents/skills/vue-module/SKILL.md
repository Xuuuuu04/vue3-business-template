# 开发包

不要复制目录，也不要手改 `scaffold.json`。生成器登记的文件才会被接受，多出来或缺少的文件都会让启动和打包失败。

```bash
npm run new:module -- 包名 --title 中文名
npm run new:page -- 包名 页面名 --title 中文名 --layout list --task "查找并打开业务对象"
npm run new:step -- 包名 步骤名 --action 动作编号 --title 中文名
npm run docs                       # 生成图和函数位置（新建包、页面、步骤之后）
npm run check -- --module 包名
```

新增步骤时必须指定所属动作。新增步骤的骨架会主动失败，直到你写入真实业务。

`new:page` 的 `--layout` 可选 `blank`（默认空白）、`list`（列表）、`form`（表单）、`detail`（详情）、`overview`（总览），各自的完整结构见[页面配方](../../../doc/ui-recipes.md)。不传参数时仍生成空白页。页面只接受 `--title`、`--layout`、`--task`；未知参数、未知布局，以及参数缺值或重复，都在写文件前失败。

用 `--task` 写此页唯一的用户任务；省略时登记为待填写。标题与任务含空格时加引号。生成器同步登记页面和组件；列表没有模拟数据，表单样板字段停用且没有保存入口，详情还没有对象查询。按真实规则替换字段与状态、接入动作后再提供主要操作，不能把这些起点当成已完成的功能。

## 固定文件

| 文件 | 用途 |
| --- | --- |
| `module.ts` | 页面、动作、接口、依赖、文件登记；页面用到的组件名必须登记在这里 |
| `public.ts` | 其他包允许使用的能力 |
| `data.ts` | 输入、公开数据、动作中间数据的类型（Zod） |
| `api.ts` | 接口路径与响应类型，与后端一致 |
| `demo.ts` | 演示模式下各接口的样例回包，键是接口编号；固定值回 200 JSON，函数可按请求返回 `Response`。只给开发服务用，页面和步骤不能导入 |
| `flow.ts` | 字段含义、输入输出、动作和步骤顺序 |
| `state.ts` | 页面动作实例与并发规则 |
| `steps/` | 命名的业务步骤 |
| `pages/` | 页面，只管输入与展示 |
| `tests/` | 按业务功能组织的确认样例 |

## 写之前

先写 `doc/包名/rules.md`：规则编号、异常情况、确认样例。没定的标"待确认"，不要自己补业务含义。步骤里的 `rule: "R-01"` 要对得上。

## 写的时候

- 动作输入用 strict 的 Zod 对象，字段写中文含义，敏感字段声明 `secret`。
- 步骤只读 `reads`、只写 `writes`，必须真的产生声明的输出；不 return；不原地修改读到的对象或数组。
- 请求只能通过步骤的 `tools.request` 发出。查询用 `latest`（新请求取消旧请求），写入用 `submit`（写入动作不能用 `latest`）。
- 写入中断、超时、成功响应无法解析都是"结果未知"，先查询，禁止自动重发。已有写请求成功后后续步骤失败，整个动作也不能重发。
- 页面只管展示输入，通过只读动作状态显示结果；业务请求和关键计算进入步骤。
- 包与包之间只用已声明依赖的 `public`。业务代码只导入 `@/shared/public` 与 `@/shared/ui/public`。

页面登记必须写 `task`，说明该页唯一的主要任务；生成页面中的提示需要按真实业务填写。页面怎么写看 `vue-ui`。生成器只给结构起点，不能把样板输入、默认提示和空页面当作成品；按真实内容完成视觉与操作检查。
