# 前端迁移

按业务项逐个迁入、对照新旧行为并联合后端验证，对齐先对齐再动手与跟着已有印象走。

默认由单一执行者接手一个完整业务包（读规则、拆步骤、拼页面、接后端并联合验证），每次迁完一项用户可操作、可验证的功能再推进下一项，不整批搬旧组件或空写整套框架。

## 迁移流程

1. **读旧实现并划定最小闭环**。查看旧前端页面、路由、请求与状态并记下对应版本，列出用户操作与后台接口，拆出最小可交付功能（例如列表查询 → 筛选勾选 → 批量提交 → 看历史记录）。
2. **先登记计划与确认样例**。在 `project-plan.json` 登记业务线与待迁动作，在 `doc/包名/rules.md` 写清规则编号、异常分支和确认样例，尚未明确的标为"待确认"并停下来确认；中途发现的新问题只记录是否影响当前迁移，不顺手扩大改动范围。
3. **按新结构拆分旧代码**：

| 旧代码形式 | 迁入方式 |
| --- | --- |
| 页面内直连 `fetch`/`axios`、改全局状态或混写计算 | 请求和关键计算拆入 `steps/`，状态托管给 `state.ts`，页面只负责展示 |
| 手写表格、筛选栏、弹窗或抽屉 | 改用界面系统的 `DataTable`、`FilterBar`、`UiDialog`、`UiDrawer` 表达 |
| 硬编码颜色、字号与间距 | 映射为公共主题与排版变量；品牌要求改在 `app.config.ts` 调整 |
| 已知有缺陷或拆分成本过高 | 写明规则变更点，对照确认样例按新模板结构重写 |
| 重复、废弃或本期不需要的功能 | 舍弃不迁 |

4. **保留用户认可的旧体验**。旧页面清晰的排版组织与品牌感知可借公共组件保留，筛选写进 URL、返回恢复位置、批量顺序处理、防连点及 `unknown` 恢复等安全规则照样写进规则与样例；渲染结果按 [界面系统](../vue-ui/SKILL.md) 用真实长度内容同视口对照。
5. **尽早联调验证**。先用演示模式跑通交互，再接入隔离的真实后端（见 [对接后端](../vue-backend/SKILL.md)）验证请求、权限与保存结果。

## 验收

分项列出功能实现状态、联调测试结果、新旧行为对照与切换情况，并标明源码版本、实跑命令与通过数；缺少真实后台或账号环境的保持"未验证"。
