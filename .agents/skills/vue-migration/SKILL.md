# 前端迁移

每次迁完一项用户能检查、能使用的业务，并保留已确认的行为。默认由一个代理从头负责：理解业务、写包、接后端、联合验证。不清空已有成果，不整批搬组件，不做全面重写。

## 开始一项业务

1. 读旧前端里这项业务的页面、路由、请求、状态，记下读的是哪个版本。
2. 列出用户的操作和对应的后端接口，选出最小的完整业务（例：查看价格表 → 筛选 → 勾选 → 批量调价 → 看调价历史）。
3. 在 `project-plan.json` 登记业务线与待迁入的动作；在 `doc/包名/rules.md` 写规则编号、异常、确认样例；未确认的标"待确认"。
4. 条件确认后保持稳定。中途发现新问题，说明它是否影响当前业务，不要悄悄扩大范围。

## 旧代码怎么处理

| 旧代码 | 处理 |
| --- | --- |
| 页面里直接 `fetch`/`axios`、改全局状态、混着计算 | 请求和关键计算拆进步骤，状态放 `state.ts`，页面只展示 |
| 手写的表格、筛选、弹窗、抽屉 | 使用界面系统的 `DataTable`、`FilterBar`、`UiDialog`、`UiDrawer`；已确认的视觉要求通过公共组件实现 |
| 写死的颜色、字号、间距 | 转成公共主题与排版规则，保留已确认的品牌和阅读层级；品牌色可设为自定义品牌色 |
| 已知有错，或拆开比重写还贵 | 单独说明规则有什么变化，按确认样例重写 |
| 重复、没用、这期不需要 | 不迁 |

用户确认的视觉参考也是验收要求；旧页面清楚的组织、品牌和排版可以吸收，不能只因迁移就抛弃。行为仍须保留：筛选条件保留、返回位置、批量操作、重复点击保护、结果未知的处理。迁的时候把行为写成规则和样例，画面按 vue-ui 使用相同内容比较。

## 联合验证

尽早把页面、动作、接口放在一起验证：先用演示服务跑通，再接隔离的真实后台（见 `vue-backend`）。各个包单独通过不能代替一起运行的结果。

## 记录和汇报

每项业务分别说明是否已实现、是否通过联合检查、是否与旧页面对照、是否已正式切换，并写明代码版本、检查命令和结果。没拿到真实后台、账号或环境的保持"未验证"；汇报先说用户哪个操作现在能做、结果是什么、卡在哪里。
