# 模板入门

按固定目录理解代码流向并跑通首项业务，对齐第一眼就懂和先对齐再动手原则。

本模板把业务包、共用能力、界面系统和开发工具分层，业务改动围绕用户能操作的一项具体任务推进。

1. **摸清目录与登记结构**。先读根目录 `AGENTS.md`，运行 `npm run project -- --json` 看总体，再按需加 `--module 包名` 展开；目录职责如下：
   - `src/modules/包名/`：业务开发包，文件固定且由生成器创建；
   - `src/shared/`：动作执行、请求、状态、导航与运行记录等共用能力；
   - `src/shared/ui/`：界面系统，包含主题、基础控件与版式组件，说明见 `src/shared/ui/README.md`；
   - `src/app/`：应用入口、外壳、路由、开发工具页与业务包登记 `catalog.ts`。
2. **顺着单向数据流改业务**。页面输入经 `state.ts` 进入动作执行，先过权限和输入校验，再顺序运行命名步骤，经 `tools.request` 调已声明接口并校验响应类型，最后通过只读状态更新页面。步骤声明读写字段、直接修改传入工作状态，普通格式化保留为普通函数。
3. **先跑通一项完整业务**。按该业务依赖确定开发顺序，规则与样例写清在 `doc/包名/rules.md`，开发计划记在 `project-plan.json`。只读当前业务需要的文件；完成后更新规则与测试路径，再运行 `npm run docs` 生成结构与计算图。
4. **启动本地演示服务验证**。确认 Node.js 为 22.12 以上的 22.x、24.x 或 26.x 后执行 `npm ci && npm run dev`，访问 `http://127.0.0.1:5180`。演示服务读取各包 `demo.ts` 回包、每次重启恢复初值；未声明样例的接口返回 404 JSON。生产构建传入 `VITE_API_MODE=real`，构建产物不包含演示数据。
5. **按任务切换对应 Skill**。新建开发包、页面或步骤看 `vue-module`，做页面与视觉对比看 `vue-ui`，跑检查与写测试看 `vue-check`，查总览和影响看 `vue-project`，旧系统迁移、后端联调与建新产品分别看 `vue-migration`、`vue-backend`、`vue-template`。
6. **区分本机与团队文件**。向外复制项目脚本与说明只带走 `.agents/skills/`；本机的任务记录、检查结果（`var/`）和临时目录留在本机。

## 验收

本地服务可正常启动并完成首项业务操作，且只在用户明确授权的范围内对接真实环境或执行写操作。
