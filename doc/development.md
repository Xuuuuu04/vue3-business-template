# 开发一个业务包

先运行 project 看总体，再用生成器创建开发包。主代理给出业务规则、确认样例、所属动作、允许修改的文件和验收命令；局部代理不决定共享策略。

## 固定文件

| 文件      | 用途                                 |
| --------- | ------------------------------------ |
| module.ts | 页面、动作、接口、依赖、固定文件登记 |
| public.ts | 允许其他包使用的明确能力             |
| data.ts   | 输入、公开数据与动作中间数据类型     |
| api.ts    | 同源 HTTP 接口和响应类型             |
| flow.ts   | 字段含义、输入输出、动作和步骤顺序   |
| state.ts  | 页面动作实例、并发规则与只读状态     |
| steps/    | 命名的业务步骤函数                   |
| pages/    | 输入与展示，不直接执行请求           |
| tests/    | 按业务功能组织的确认样例             |

每个动作输入使用 strict 的 Zod 对象。字段都写中文含义，敏感字段声明 secret。每个步骤列出 reads、writes、uses 和规则编号。输出通过写入字段产生；多次写同一字段或覆盖输入不允许。读到的对象与数组不能原地修改。可选分支使用命名条件，复用相同条件定义，结果必须在所有路径存在。

计算图只放有业务意义的步骤，普通格式化函数继续保持普通函数。需要单独定位和调优的计算拆成命名步骤。每个步骤有文件、函数和行号，由工具自动生成；普通赋值和 DOM 事件不逐个记录。

## 页面和状态

所有外部请求经过步骤 request；响应先检查类型再变成业务结果。最新读取取消先前读取，旧响应不能覆盖新条件。提交中不能重复点击；写入请求丢失结果、服务端 5xx、请求超时响应、成功响应无法解析都属于结果未知，禁止自动重发。明确的后台失败保留输入，提供修正或再次读取的方法。

共用执行器根据本次实际请求结果处理整体失败：已有写请求成功时，后续步骤或输出类型失败、第二接口明确拒绝，都不能整体重发。整体保留 unknown（未全部完成），提示已有后台写入操作成功、后续失败及先查询；步骤保留原错误，成功请求仍记为 ok，后续请求保留各自结果。没有成功或未知写入的输入、计算与发送前错误可修正重试。不得只根据最后一个异常判断动作是否可重发。

保留旧查询数据用于列表加载或同对象刷新时，详情展示和操作须验证结果编号属于当前路由。切换对象关闭旧确认；删除使用确认时的对象编号，下载编号和名称取自点击时的同一对象，不在等待结束后重新读取变动的详情。

列表筛选和分页写入 URL。浏览器返回恢复 URL 与滚动位置。详情支持直接访问与刷新。未保存的文件选择覆盖页面导航和浏览器关闭提醒；文件内容不写入浏览器存储。

业务页面从共用 UI 入口取组件，用版式组件拼页面，不写 CSS 类和样式。页面登记写 task；一个 PageFrame workspace 只有一个 WorkArea 或 DataTable 主区。业务页禁止 Card、正文前说明段落和多个 primary。默认正文与输入控件 16px，辅助文字不小于 12px。颜色、圆角、疏密只在主题中声明，产品可以选配色或指定品牌色。公共组件新增前确认已有组件是否已经能够表达任务。组件清单和拼装规则见 src/shared/ui/README.md。

## 图、运行与检查

浏览器测试放在 `tests/browser`。公共组件、登录与安全检查不依赖样板业务；只验证样板业务的浏览器用例集中在 `tests/browser/demo`，样例接口登记的本地检查放在 `tests/demo`。模板运行公共及样例检查；`start:project` 整体删除两个 demo 目录，新产品继续执行全部公共检查与现有 CI。公共工具的已知输入放在受保护的 `tests/framework/fixtures`，不导入样例业务。新增业务用例按真实产品编写，不把样例测试混入公共文件，也不为初始化成功而跳过公共检查。

project 输出实际登记图、业务计划和真实检查情况。检查结果包含源码指纹；代码改变后旧结果明确标为过期。单包检查不会被写成全仓检查。运行详情包含动作、步骤、条件是否跳过、输出安全摘要、错误、请求时间及后台编号。后台不返回编号时保持缺失。

运行时间为实际 performance 时间。请求等待包含后台时间，不与后台步骤相加。浏览器性能事件与动作计算分开显示；navigation-dom 只表示页面 DOM 更新完成，不保证已经绘制。Vue 的开发性能标记用于更细的组件分析。

## 添加文件

开发包、页面和步骤均使用脚本。每个包有一个 `demo.ts`，按接口编号写演示模式下的样例回包，开发服务统一提供；页面和步骤不能导入它，生产打包不带。生成器登记表受到框架文件保护；乱建文件、手改文件清单与未登记包会阻止启动和打包。新增步骤骨架会主动失败，直到实现对应业务。生成器不会擅自决定业务规则。

增加页面时可以直接选择任务对应的版式，例如：

```bash
npm run new:page -- contacts history --title 联系记录 --layout list --task "查找并打开联系记录"
npm run docs
npm run check -- --module contacts
```

`contacts` 需要已经通过 `new:module` 创建。`--layout` 支持 `blank`、`list`、`form`、`detail`、`overview`，默认 `blank` 保持原来的空白页用法；各自的完整结构见[页面配方](ui-recipes.md)。页面和组件同时登记。不传 `--task` 时仍需补上待填写的页面任务。页面只接受 `--title`、`--layout`、`--task`；未知参数、未知布局，以及参数缺值或重复，都会在写入任何文件之前报错。

这些版式只有展示结构：列表还未接入数据，表单的样板字段停用且尚无保存操作，详情还没有对象查询。按已确认规则替换字段、声明查询或提交动作，补上加载、失败、结果未知等状态后，再提供真实操作入口。样板不生成模拟请求、成功提示或可点击的空保存按钮。

## 迁移大项目

先按使用者任务确定页面与业务包，在 project-plan.json 列出业务线和待迁入动作。主代理确认公共接口和依赖方向，再逐包迁移。包间只走 public；不把旧项目全局变量搬成前端全局可写对象。旧系统可比较行为，业务正确仍依据规则和确认样例。

每个包独立检查并交付，再验证包之间的共同操作。旧结果、测试数量和代码行数都不能证明迁移正确。规模增长时 project --module 提供限定范围，浏览器图按包和动作展开，避免一次读取所有源码。

保存时结构检查也会阻止违规热更新。运行编号和导出的记录可交给 `npm run runs -- --file 记录.json --run 编号`；改动影响使用 `npm run impact -- --base main`。

页面离开取消读取；已提交的写入继续取得真实结果并记录，只停止向离开的页面更新。写入动作不能采用 latest 模式。
