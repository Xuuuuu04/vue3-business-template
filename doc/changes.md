# 变更说明

## 2026-10-07：新的界面系统，替换 Element Plus

- 新增 `src/shared/ui` 界面系统：主题（七套配色，圆角、疏密、侧栏风格独立可选，也可自定义品牌色）、基础控件、版式、数据表格、筛选条、图表、可收起的侧栏外壳和登录布局。组件说明与拼装规则见 `src/shared/ui/README.md`。
- 必须修改共用部分的原因：原来用 Element Plus 改样式，改不出需要的质感；界面也没有统一的拼装规则，页面一多就松散。控件的键盘与读屏行为改由 Reka UI 提供，外观由模板自己的组件决定。
- 字号规则由"16px 起"改为"正文 14px 起，辅助文字不小于 12px"：企业后台以表格和表单为主，14px 能在一屏放下足够信息。
- 页面规则收紧：业务页面不能写 `class` 与 `style`，页面标题下面不放说明小字，状态事实放进状态行。检查会拦下违规页面。
- 文件管理样板页改用新组件；`PageFrame` 不再接受 `description`；`UiTable`、`UiColumn`、`UiOption`、`UiPagination` 的旧用法由 `DataTable`、`UiSelect` 的 `options`、`UiPagination` 的新用法替代。生成器的页面模板同步更新。
- 新增浏览器测试：每套配色在浅色、深色和三种侧栏下的文字对比度（正文 4.5:1，提示 3:1）；主题与侧栏收起状态切换并被记住。原有 8 个文件管理浏览器测试按新页面更新选择方式，业务规则不变。
- 新增前端项目 Skill（`.agents/skills/vue-*`，共 8 个），新产品创建时随框架复制，并纳入框架保护记录。
- 未做：接口登记仍是手写，没有从后端 openapi 生成；表单字段级错误（后端 `fields`）还没有接到 `Field`；暗色模式只检查了文字对比度，没有逐页检查截图。
- 检查命令：`npm run docs`、`npm run check`、`npm run test:browser`、`npm run build:demo`。结果见本机检查报告；演示服务不等于真实后台验收。

## 2026-10-05：写入后失败与详情对象身份

- 共用执行器依据本次实际请求记录判断已有保存。已成功写入后，计算、产出类型或第二写请求失败，保留后续错误和成功请求事实，禁止整体重发；没有成功或未知写入的失败仍可修正重试。未知写请求的既有处理不变，离开页面仍继续记录已提交写入。
- 必须修改共用执行器的原因：只有它同时知道本次所有真实请求和后续步骤结果。页面只看到最后异常，单独补按钮会让其他提交入口继续重复保存；本次不添加恢复平台或后台接口。
- 详情只展示属于当前路由编号的文件，切换编号关闭旧确认。删除请求使用已显示、已确认的对象；下载使用点击时的文件编号和名称。列表及同一对象刷新仍可保留旧数据。
- 在现有并发功能测试与文件浏览器测试中扩展回归，不增加业务模块文件、不改业务样板来制造场景。浏览器使用真实 SPA 参数切换，并在测试内控制 B 的慢读取、403、删除请求与等待中的下载。
- 旧实现证据：四个成功写入后失败样例均错误成为可重发 error；SPA 切换慢/成功读取后旧删除确认仍可见，等待中的 A 下载被命名为 B。
- 检查命令：`npm run docs`、`npm run check`、`npm run test:browser`、`VITE_API_MODE=real npm run build`、Skill 的 `change_health.py`。实际结果由本机检查报告及交接记录提供，演示 HTTP 测试不等于真实后台验收。
